## 2. 🔴 seen/unseen 격차 — 전체 평균은 낙관적이다

Phase 3에서 추가한 분해축이 바로 값을 했다. PP-OCRv6 기준:

```
seen   Exact 67.2%   (라벨을 train 에서 본 짧은 계열 코드)
unseen Exact 35.8%   (train 이 못 본 코드)          <- 격차 31.4%p
전체   Exact 49.7%
```

전체 49.7%만 보면 실제 일반화 성능(35.8%)을 **14%p 과대평가**한다.
이후 모든 리포트는 이 축을 함께 싣는다.

## 3. 🔴 길이별 분해 — 후단 매칭이 흡수하는 지점이 정반대였다

PP-OCRv5 기준, 라벨 길이로 쪼갠 결과:

| 라벨 길이 | n | CAR | Exact | Top-1 | Top-5 | DB 최근접 이웃 거리 |
|---|---|---|---|---|---|---|
| 1–2 | 42 | 0.905 | **88.1%** | 88.1% | 88.1% | 0.370 |
| 3–4 | 367 | 0.831 | 64.6% | 73.0% | **82.8%** | 0.276 |
| 5–8 | 117 | 0.812 | 44.4% | 80.3% | 88.9% | 0.258 |
| 9–14 | 153 | 0.779 | **13.1%** | 82.4% | **94.1%** | 0.227 |
| 15–40 | 83 | 0.774 | 6.0% | 79.5% | 89.2% | 0.179 |

**Exact 와 Top-5 가 반대 방향으로 움직인다.**
긴 코드는 Exact 13%인데 Top-5 는 94%, 짧은 코드는 Exact 65%인데 Top-5 는 83%다.

이유는 오른쪽 열이다. 긴 코드는 후보 공간에서 **정보량이 커서 이웃이 멀고**(거리 0.179),
몇 글자 틀려도 매칭이 정답을 복원한다. 짧은 코드는 `901`/`902`/`903`, `(1)`/`(7)` 처럼
**이웃이 조밀해서**(거리 0.370) 한 글자만 틀려도 Top-5 밖으로 밀린다.

### 이것이 뒤집는 전제

지시서 TASK 5는 **"긴 복합 코드"를 합성 보강 우선순위 상위**에 뒀다
(*"20자+ 코드 대부분 유일값 → 코드 문법으로 긴 조합 대량 생성"*).
모델 KPI(Exact) 관점에서는 맞다. 그러나 **시스템 KPI(Top-5) 관점에서 긴 코드는 이미
94%로 가장 좋고, 병목은 길이 3–4 구간(test 의 48%, Top-5 82.8%)** 이다.

> **TASK 5 반영 사항**: 합성 데이터의 목적을 "Exact 를 올릴 것"과 "Top-5 를 올릴 것"으로
> 나눠 봐야 한다. Top-5 를 올리려면 **짧은 계열 코드의 혼동 문자 정확도**가 핵심이며,
> 이는 지시서가 이미 2순위로 둔 "희소 혼동 문자 균형 생성"과 일치한다.
> 긴 코드 생성은 Exact 개선에는 기여하지만 Top-5 개선 효율은 낮다.

## 4. 혼동 문자 오인식 — 최우선 감시 지표

지시서 TASK 4-2가 요구한 혼동행렬. 이 오인식은 **다른 실존 부품으로의 오분류**를 뜻한다.

| 모델 | 총 치환 | 주요 축 (상위 5) |
|---|---|---|
| PP-OCRv4 | 225 | `1→I` 55, `0→O` 43, `5→S` 36, `8→B` 35, `S→5` 16 |
| PP-OCRv5 | 159 | `1→I` 42, `S→5` 31, `0→O` 20, `5→S` 14, `8→B` 13 |
| PP-OCRv6 | 168 | `S→5` 51, `1→I` 45, `8→B` 25, `5→S` 11, `0→O` 10 |

- **`1→I` 가 전 모델 공통 최다**. 범용 OCR 이 숫자 1 을 대문자 I 로 읽는 경향.
- v4 는 `5→S`(36) 우세, v6 은 `S→5`(51) 우세로 **방향이 뒤집힌다**. 세대별 사전/학습
  데이터 차이로 보이며, fine-tuning 시 이 편향이 어느 쪽으로 붙는지 추적해야 한다.
- 총량은 v5(159) < v6(168) < v4(225). v6 이 v5 보다 총량이 많은데도 Exact 가 높은 것은
  혼동축 외 오류가 줄었기 때문이다.

> 이 축들은 `8135`/`B13S` 처럼 **둘 다 실존하는 코드를 가르는 구별축**이므로,
> TASK 6-C 의 혼동 문자 집중(loss 가중/hard example mining)을 **1단계부터** 켠다.

## 5. 🔴 곡면 서브셋 — 목표선을 point estimate 로 세울 수 없다

| 모델 | 곡면 CAR | 곡면 Exact |
|---|---|---|
| PP-OCRv4 | 0.5591 | 11.1% (9건 중 1건) |
| PP-OCRv5 | 0.5071 | **0.0%** |
| PP-OCRv6 | 0.6085 | **0.0%** |

test 곡면 박스는 **9개**다. Exact 11.1% 와 0.0% 의 차이는 정확히 **1건**이다.
Phase 3에서 5-Fold 를 채택한 이유가 여기서 실증됐다.

- 기획서 3.3의 곡면 목표선 *"하락 없음(회귀 방지)"* 는 baseline 이 0.0% 인 지금
  **의미가 없다**. 0에서 시작하므로 "하락 방지"가 아니라 "달성"이 목표다.
- 곡면 지표는 앞으로 **5-Fold 평균±표준편차**로만 보고한다. 단일 분할 수치는 추세 확인용.
- 평면(50.3%) 대비 곡면(0.0%) 격차가 절대적이므로, **곡면은 이 프로젝트의 최대 병목**
  이라는 기획서 전제가 실측으로 확인됐다.

## 6. 목표선 확정 (기획서 3.3 표 채우기)

\|DB\| = 4,171 로 확정됐고 Phase 4의 Top-K 응답 곡선이 나왔으므로 재보정한다.

| 지표 | Baseline (PP-OCRv4) | 목표선 (확정) | 근거 |
|---|---|---|---|
| CAR | **0.7565** | **≥ 0.90** | Top-5 95% 의 전제인 Exact 64% 를 지탱하려면 필요 |
| Exact-match | **35.3%** | **≥ 64%** | Phase 4 응답 곡선에서 역산 (아래) |
| Top-5 (폐집합) | **82.4%** | **≥ 95%** | 기획서 초안 유지 |
| Top-1 (폐집합) | **70.7%** | **≥ 85%** | 기획서 초안 유지 |
| 곡면 Exact (5-Fold) | **0.0%** | **≥ 30%** (신규) | "하락 없음"은 baseline 0 에서 무의미 |
| 혼동 문자 치환 | **225건** | **≤ 110건** (절반) | 최우선 감시 |

### Exact ≥ 64% 가 목표선에 들어간 이유

Phase 4에서 잰 Top-K 응답 곡선(\|DB\|=4,171):

```
완벽 인식     Top-5 100.0%
1글자 오인식  Top-5  86.0%
2글자 오인식  Top-5  66.5%
```

오류가 **전부 1글자짜리라고 낙관해도** `0.95 = p×1.00 + (1−p)×0.86` → **p = 64%**.
따라서 Top-5 ≥ 95% 는 Exact ≥ 64% 없이는 도달 불가능하다.
**Exact 를 "참고" 지표로 두라는 기획서 3.1의 위치 설정은 이 데이터에서 성립하지 않는다** —
Top-5 목표의 직접적 제약이므로 승격한다.

현재 v4 35.3% → 64% 는 **+28.7%p**. 도메인 특화 fine-tuning 의 통상 개선폭 안이지만
낙관적이지 않은 목표다. TASK 6 1단계 완료 시점에 이 궤도에 있는지로 F2 폴백을 판단한다.

## 7. 🟡 Phase 0 프레임워크 결정 재검토 트리거

Phase 0은 "RARE/TPS 4단계를 살리려면 2.x 외 선택지 없음"을 근거로 PaddleOCR 2.10.0을
택했다. 그 **비용이 이제 측정됐다**:

| | Exact | Top-5 |
|---|---|---|
| PP-OCRv4 (2.x 최대) | 35.3% | 82.4% |
| PP-OCRv6 (3.x) | 49.7% | 90.4% |
| **차이** | **−14.4%p** | **−8.0%p** |

즉 2.x 를 택한 대가로 **baseline 을 14.4%p 뒤에서 시작**한다. 반면 얻는 것(4단계 RARE
교체 실험)은 **효과가 검증되지 않은 선택지**다. 게다가 Phase 0에서 확인했듯 2.x 의
`rec_svtrnet.yml` 에는 이미 `STN_ON` 정류가 내장돼 있어, 곡면 대응은 4단계 없이도 1단계부터 들어간다.

> **판단 보류, 결정 시점 지정**: 지금 뒤집지 않는다. fine-tuning 후 격차가 좁혀질 수
> 있고(도메인 적응이 세대 차를 흡수), 지금 바꾸면 Phase 2~4 산출물의 전제가 흔들린다.
> **TASK 6 1단계 완료 시점**에 fine-tuned v4 가 무조정 v6(Exact 49.7%)를 넘지 못하면,
> 4단계(RARE)를 포기하고 3.x/PaddleX + PP-OCRv6 으로 전환하는 것을 F2 폴백의
> 선택지로 정식 검토한다.
