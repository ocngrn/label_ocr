# TASK 4-3 [게이트] — 검출 fine-tuning 필요성 판단

> 지시서 `claude_code_prompt_paddleocr_colab.md` TASK 4-3.
> 실측 일자: 2026-08-01 / 모델 `PP-OCRv5_server_det` (기본 추론 설정) / IoU ≥ 0.5
> 원본 수치: `reports/baseline_det_metrics.json`

---

## 결론

### **검출 fine-tuning 필요 — 단, 착수 전에 추론 해상도부터 확인할 것**

평면 서브셋 recall 71.1% 로 지시서 임계값(Hmean ≥ 95%)에 **크게 미달**한다.
따라서 TASK 6-A(2단계 검출 fine-tuning)는 **생략하지 않는다.**

다만 저비용 원인 후보(추론 해상도)가 남아 있어, **fine-tuning 착수 전에
Colab GPU 에서 해상도 스윕을 먼저 수행**한다(지시서 F5 (a) — "재학습보다 저비용").

---

## 1. 평가 설계

| 항목 | 값 |
|---|---|
| 평가 이미지 | **318장** = test 234 + 곡면 이미지 93 (중복 9 제외) |
| GT 박스 | 1,022 (평면 923 / 곡면 99) |
| 매칭 | 폴리곤 IoU ≥ 0.5, 그리디 1:1 |

### 곡면 이미지를 전량 넣은 이유
test 에 배분된 곡면 박스는 **9개**뿐이라 곡면 검출 판단이 통계적으로 불가능하다
(예측 1건이 11%p). 지금은 사전학습 모델을 그대로 재는 baseline 이라 학습이 일어나지
않았으므로, **곡면 99박스 전량**을 평가에 써도 누수가 없다. 이로써 곡면 판단이
n=9 → n=99 로 의미를 갖게 된다.

---

## 2. 실측 결과

| 서브셋 | GT | TP | **recall** |
|---|---|---|---|
| **평면 (4점)** | 923 | 656 | **71.1%** |
| **곡면 (5점 이상)** | 99 | 21 | **21.2%** |
| 전체 | 1,022 | 677 | 66.2% |

전체 precision 52.3% / Hmean 58.5% (예측 1,294건).

---

## 3. 판단

### 평면 — 지시서 기준 미달 → fine-tuning 대상

지시서 판단 기준:
> 평면 서브셋 Hmean ≥ 임계값(예: 95%) → 평면 검출은 fine-tuning 생략
> 평면 서브셋이 임계값 미달 → 검출 fine-tuning 필요

**71.1% 는 95% 에 24%p 미달**이다. 지시서가 미달 사유로 예상한
*"조밀한 다중 박스 레이아웃·박스 간 근접에서 recall 저하"* 가 실제로 관측된다.

> 리소스 배분에 대한 지시서의 기대(*"평면 검출이 충분하면 인식에 리소스 집중"*)는
> **성립하지 않는다.** 검출도 병목이다.

### 곡면 — 도메인 시프트 확인, 저비용 경로 우선

곡면 recall **21.2%** 는 평면(71.1%)의 1/3 이하다. 지시서가 예상한 대로다:

> 곡면 서브셋은 별도 판단: 사전학습 검출기가 곡면에서 유독 낮으면(도메인 시프트
> 가능성 높음), 전체 재학습이 아니라 곡면 증강 데이터만으로 짧게 이어서 학습
> (continued training)하는 저비용 경로를 우선 검토

곡면 99박스 중 **78개를 아예 놓친다.** 검출 단계에서 놓치면 인식이 아무리 좋아도
end-to-end 는 실패하므로, **곡면 최대 병목은 인식이 아니라 검출**일 가능성이 크다.
(TASK 4-2 인식 baseline 에서 곡면 Exact 0.0% 였는데, 이는 GT 크롭을 준 조건이었다 —
실제 파이프라인에서는 그 앞에서 78.8%가 이미 유실된다.)

## 4. 🟡 fine-tuning 착수 전 확인할 것 — 추론 해상도

`PP-OCRv5_server_det` 의 배포 config 는 다음과 같다:

```yaml
DetResizeForTest: {resize_long: 960}
```

원본 이미지는 **2560×1920** 이므로 긴 변이 **2.67배 축소**된다. 라벨 코드는 이미지
안에서 작게 찍혀 있어(이미지당 평균 3.5박스, 박스가 화면의 일부만 차지),
축소 후 텍스트 획이 뭉개져 recall 이 깎였을 가능성이 있다.

**이는 재학습 없이 파라미터만으로 해소될 수 있는 원인**이므로, 지시서 F5 (a)
("DB 후처리 파라미터 튜닝 우선 시도 — 재학습보다 저비용")에 따라 먼저 확인해야 한다.

### 검증 미완료 — 사유: 로컬 CPU 성능 한계

`limit_side_len` 을 960 / 1536 / 2048 로 스윕하려 했으나 **완주하지 못했다.**

| 설정 | 상태 | 소요 |
|---|---|---|
| 960 (기본) | 완료 (표본 20장) | 193s |
| 1536 | **미완** — 40분 경과 후에도 20장 미완료 | 중단 |
| 2048 | 미실행 | — |

로컬은 `paddlepaddle 3.3.1` **CPU 빌드**이고 검출 모델은 oneDNN 경로마저 깨져
(`enable_mkldnn=False` 강제) 고해상도 추론이 사실상 불가능하다.

> **다음 세션 작업 지시**: Colab GPU 에서 `limit_side_len ∈ {960, 1536, 2048}` ×
> `box_thresh`, `unclip_ratio` 스윕을 먼저 수행한다. GPU 에서는 수 분이면 끝난다.
> - 평면 recall 이 해상도만으로 95% 에 도달 → **TASK 6-A 생략**, 추론 설정만 고정
> - 도달하지 못함 → 예정대로 TASK 6-A(2단계) 진행. 이때 곡면은 전체 재학습이 아니라
>   **곡면 증강 데이터 continued training** 경로를 우선 시도

## 5. precision 52.3% 에 대한 유보

예측 1,294건 중 677건만 GT 와 매칭됐다. 다만 표본 3장을 육안 확인한 결과
(GT 초록 / 매칭 파랑 / 미매칭 빨강) **미매칭 예측이 보이지 않았고 TP 가 4/5, 5/5, 4/4**
였다. 즉 평면 test 이미지에서는 과검출이 거의 없다.

낮은 precision 은 **곡면 이미지 쪽에 몰려 있을 가능성**이 크다. 파이프·원통 사진에는
라벨링되지 않은 각인·인쇄 텍스트가 함께 찍혀 있어, 검출기가 그것들을 잡으면
GT 에 없으므로 전부 FP 로 계산된다.

> **주의**: 이 경우 precision 저하는 **모델 결함이 아니라 라벨 커버리지의 한계**다.
> TASK 6-A 착수 시 미매칭 예측을 표본 검토해 "진짜 오검출"과 "미라벨 실제 텍스트"를
> 구분한 뒤 precision 목표선을 정한다. 지금 수치로 precision 목표를 세우지 않는다.
> **판단의 1차 근거는 서브셋 recall** 이며, 이는 GT 기준이라 이 문제의 영향을 받지 않는다.
