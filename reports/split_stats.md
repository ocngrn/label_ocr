## 0. 먼저 오해 방지 — **제외되는 데이터는 없다**

아래에 "길이 5자 이상만 식별 시리얼로 간주한다"는 규칙이 나온다. 이것은
**학습·평가에서 무엇을 뺄지가 아니라, 이미지를 어느 split 에 넣을지 정할 때
무엇을 기준으로 묶을지**를 정하는 규칙이다. 전체 8,102박스가 하나도 빠짐없이
train 6,523 + val 817 + test 762 로 들어간다.

| | 그룹화 대상? | 결과 | 학습에 쓰이나 | 평가에 쓰이나 |
|---|---|---|---|---|
| `H32C-52` (7자) | ✅ | 28장 **전부 train** → test 에 없음 | ✅ | — |
| `EL 8166 P77-04` (14자) | ✅ | 23장 **전부 test** → train 이 못 봄 | — | ✅ |
| `8166` (4자) | ❌ | train 66 / val 8 / **test 7** 로 분산 | ✅ | ✅ |
| `(1)` (3자) | ❌ | train 41 / val 8 / **test 8** 로 분산 | ✅ | ✅ |

즉 `8166` 은 **train 에서 학습되고 test 에서도 평가된다.** 다만 test 의 `8166`
크롭 7개는 "모델이 이미 본 적 있는 문자열"이라는 점이 다를 뿐이다.
이 낙관은 3장에서 정량화하고, 지표를 seen/unseen 으로 분해해 보고한다.

## 2. 지시서 규칙의 완화 — 문자 그대로는 실행 불가능했다

지시서 TASK 2-1은 "**시리얼 값 단위 그룹 분할** + 이미지 단위 분할 병행,
동일 시리얼이 train/test 동시 등장 금지"를 요구한다.

### 문제: 그대로 하면 74.4%가 한 덩어리가 된다

한 이미지에 평균 3.46개 박스가 있고 계열 코드가 수십 장에 반복되므로,
"시리얼을 공유하는 이미지는 같은 split" 규칙을 **모든 반복 시리얼**에 적용하면
이미지들이 연쇄적으로 연결된다. 실측:

```
연결요소 474개, 최대 1,740개 이미지 (74.4%)
```

최대 요소가 74.4%면 그 하나가 train(80%)을 거의 다 차지해 분할이 성립하지 않는다.

### 원인: 짧은 코드는 식별 시리얼이 아니다

가장 많이 반복되는 값들 — 전부 **부품 계열 코드·수량 표기·순번**이다:

```
8166(75장) 8100(59) 8049(54) (1)(53) 8196(52) 8129(46)
902(34) P29(33) 3(28) E51S(26) (7)(25) 901(24)
```

이는 개별 부품을 식별하는 시리얼이 아니라 도메인 어휘다. 기획서 2장도
*"모델이 코드 사전확률(prior)을 학습해 부분 오인식을 보정할 여지"* 를 이점으로 든다.
이런 값을 train/test 에서 분리하는 것은 누수 방지가 아니라 **도메인 학습을 막고
실배포보다 비현실적으로 어려운 평가를 만드는 것**이다.

### 채택: 길이 5자 이상만 식별 시리얼로 간주

| 그룹화 기준 | 그룹 대상 시리얼 | 최대 연결요소 |
|---|---|---|
| 전체 반복 시리얼 | 933 | 1,740 (74.4%) — 분할 불가 |
| 빈도 ≤ 8 | 822 | 1,040 (44.4%) — 여전히 불가 |
| **길이 ≥ 5** | **354** | **78 (3.3%)** ← 채택 |
| 길이 ≥ 8 | 228 | 26 (1.1%) |

빈도 기준은 임계값을 올리면 급격히 무너지는 반면(빈도≤8에서 이미 44%),
길이 기준은 안정적이다. 임계 5에서의 분리가 의미적으로도 정확하다:

- **제외(길이<5)**: `8166` `8100` `(1)` `902` `P29` `E51S` `3` — 계열·수량·순번
- **그룹화(길이≥5)**: `H32C-52` `8166TE2` `EL 8166 P77-04` `8100LUA.28` `8184TE2-05` — 실제 부품 식별 코드

결과: 연결요소 1,637개, 최대 78개(3.3%) → test 목표 234장보다 작아 배분이 자유롭다.

## 3. 잔여 낙관의 정량화 — 숨기지 않고 지표로 분해한다

| 항목 | 값 |
|---|---|
| test 고유 라벨 | 577 |
| 그중 train 과 공유 | 193 (33.4%) |
| **그중 식별 시리얼(길이≥5)** | **0** ✅ |
| train 에서 못 본 라벨 | 384 (66.6%) |

**식별 시리얼 누수 0건** — 그룹 분할이 의도대로 작동했다. 공유되는 193개는
전원 4자 이하 계열·수량 코드다(`tests/test_split.py` 로 강제).

### 평가 지표는 seen/unseen 으로 분해해 보고한다

| 구분 | test 크롭 | 의미 |
|---|---|---|
| **unseen** (라벨이 train 에 없음) | **424 (55.6%)** | **일반화 성능 — 주 지표** |
| seen (짧은 계열 코드) | 338 (44.4%) | 암기 포함 — 실배포에 가까운 조건 |

전체 평균만 보면 seen 44.4% 만큼 낙관적이다. 이를 드러내기 위해
`splits/split_seed42.json` 의 `seen_in_train` 에 **크롭별 플래그**를 저장했다.
TASK 4 baseline 부터 TASK 7 최종 평가까지 CAR·Exact·Top-K 를 이 축으로 쪼개 보고한다.

> **Top-K 평가 주의(기획서 3.2)**: 그룹 분할로 학습에서 제외된 시리얼도
> **DB 프록시(`serial_db_proxy_v1`)에는 반드시 포함**해야 폐집합 Top-K 가 성립한다.
> "학습에서 뺀다 ≠ DB 에서 뺀다". → Phase 4에서 처리.

## 4. [게이트] 곡면 표본 부족 대응 — K-Fold 채택

지시서 TASK 2-3이 지적한 문제가 실제로 발생했다:

> 곡면 99박스를 8:1:1로 나누면 test 에 약 10개 내외만 남는다. 이 규모에서는
> 예측 1건의 성패가 지표를 약 10%p 흔들어 Exit Criteria 로 쓰기에 불안정하다.

**실측 결과 test 곡면 박스는 정확히 9개**다. 예측 1건이 11.1%p를 움직인다.

### 채택: 곡면 서브셋 5-Fold 교차검증 (지시서 권장 기본안)

곡면 이미지 93장을 연결요소를 쪼개지 않고 5개 폴드로 분할:

```
폴드 크기: [19, 18, 18, 19, 19]  (합 93)
```

곡면 지표는 **단일 분할 point estimate 대신 5-Fold 평균±표준편차**로 보고한다.
비용이 크므로 지시서 지침대로 **최종 후보 1~2개로 좁힌 뒤 확정 검증**에 쓰고,
배합비 스윕(TASK 6-D) 같은 반복 실험 중에는 단일 분할 수치를 추세 확인용으로만 본다.

### 안전판: Anchor 방식 (채택하지 않음, 발동 조건만 기록)

지시서의 대안(실사 곡면 99건 전량을 평가 전용 고정, 학습은 합성 곡면만)은
**채택하지 않는다**. train 곡면이 0이 되어 지시서 TASK 2-2의 "train 곡면 0 방지"와
정면 충돌하고, 합성 곡률이 실물과 어긋나면 일반화가 오히려 나빠진다는 트레이드오프를
지시서 자신이 명시했다.

**발동 조건**: TASK 6-D 에서 합성 곡면 추가 후 실사 곡면 성능이 하락하고
곡률 파라미터 재조정으로도 회복되지 않을 때 재검토한다(Fallback F3 와 연결).
