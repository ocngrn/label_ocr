# DB 유도 조각 병합 — 기하가 못 하던 일을 한다

> 실측 일자: 2026-08-05 / 로컬 CPU / 검출 캐시 `detect_cache_test.json` (PP-OCRv5_server_det)
> test 234장 / GT 762박스 / `serial_db_proxy_v1` (4,171 시리얼)

---

## 결론

| 방식 | 시스템 Top-5 | tok1 | tok2 | tok3 |
|---|---|---|---|---|
| 기하 `gap=0.0` (M2-B 최적) | 62.9% | 67% | 46% | 57% |
| 기하 `gap=1.5` | 40.3% | 32% | 62% | 67% |
| **DB 유도 병합 (무조정)** | **64.2%** | 64% | **61%** | **68%** |
| DB 유도 병합 (`margin=0.02`) | 65.9% ⚠️ | 67% | 55% | 67% |

**무조정 +1.3%p.** 작아 보이지만 **작동 원리가 다르다**는 점이 중요하다.

- 다중 토큰: tok2 **46% → 61%**, tok3 **57% → 68%**
- 그 이득을 기하로 얻으려면 `gap=1.5` 로 공격적으로 묶어야 하는데,
  그러면 단일 토큰이 **67% → 32%** 로 무너져 전체가 40.3% 로 폭락한다.
- DB 유도는 같은 다중 토큰 이득을 얻으면서 단일 토큰 손실이 **3%p 에 그친다.**

> ⚠️ `margin=0.02` 의 65.9% 는 **test 에서 고른 값**이라 정직한 test 점수가 아니다.
> 확정하려면 val 캐시가 필요하다 (아래 §4).

## 1. 왜 기하로는 불가능했나

`reports/m2b_spatial_group.md` §1 의 진단:

```
한 부품 표면의 GT = ['28', 'P32', 'C6B', '8196P32', '15']
```

`8196 P32` 는 한 박스인데 바로 옆 `P32` 는 별개다. 셋 다 같은 면에 나란히 인쇄돼 있어
**간격·정렬로는 구별할 정보가 원리적으로 없다.**

**그러나 DB 에는 있다.** `8196P32` 는 4,171개 시리얼 중에 있고 `P32C6B` 는 없다.
우리가 처음부터 가지고 있던 자산인데 병합 판정에 써본 적이 없었다.

라벨 관행 자체가 이 성질을 갖는다(실측):

```
527개 토큰(고유 토큰의 13.3%)이 단독으로도, 묶인 채로도 등장
   그 토큰들의 등장 횟수: 단독 2,914 / 묶임 2,814   ← 거의 반반
   8196 -> 단독 57회 / 묶임 120회
```

**같은 토큰이 사진마다 단독이기도 하고 아니기도 하다.** 판단 근거는 토큰 자신이 아니라
"옆 토큰이 같은 부품번호의 일부인가"이고, 그 답을 아는 것은 DB 뿐이다.

---

## 2. 방법

1. **기하는 후보 사슬만 만든다** — `group_fragments(gap_ratio=1.5)`.
   여기서 정하는 것은 "묶는다"가 아니라 "묶일 수 있는 이웃인가"다.
2. **사슬을 연속 구간으로 분할**하는 방법 중 DB 적합도가 최대인 것을 고른다.

목적함수는 **글자수 가중 DB 점수**다:

```
maximize  Σ_segment  score(segment) × len(segment)
```

이어붙여도 총 글자수가 변하지 않으므로 분할 방식이 달라도 비교가 성립한다.
단순 합은 쪼갤수록 커지고(구간마다 ≤1 이 더해짐), 단순 평균은 합칠수록 커진다.
길이 가중은 **글자 하나하나가 자기 구간의 매칭 품질만큼 기여**하게 해 그 편향을 없앤다.

최적 분할은 O(n²) DP 로 정확히 구한다. 사슬은 대개 5조각 이하다.

### 동점이면 쪼갠다

M2-B 에서 확신 없이 묶었더니 단일 토큰이 67% → 29% 로 무너졌다. 단일 토큰이 전체의
75%(568/762)라 **잘못된 병합의 손실이 이득보다 크다.** 근거가 동등하면 묶지 않는다.

> 이 규칙은 부동소수점에 깨진다. `0.7×10 = 7.000000000000001` 인데
> `0.7×4 + 0.7×6 = 7.0` 이라 수학적 동점에서 병합 쪽이 미세하게 이긴다.
> 비교에 `1e-9` 엡실론을 넣어 막았다.

## 3. `margin` — 어중간한 병합을 억제한다

조각을 둘 이상 묶는 구간에만 문턱을 물린다.

| margin | Top-5 | tok1 | tok2 | tok3 |
|---|---|---|---|---|
| 0.0 | 64.2% | 64% | 61% | 68% |
| **0.02** | **65.9%** | 67% | 55% | 67% |
| 0.05 | 65.9% | 68% | 55% | 63% |
| 0.10 | 65.5% | 69% | 52% | 60% |
| 0.20 | 63.5% | 68% | 44% | 56% |

문턱을 올리면 단일 토큰이 회복되고 다중 토큰이 줄어든다. 0.02~0.05 에서 균형이 맞는다.

---

## 4. 확정에 필요한 것

이 실험은 **PP-OCRv5 검출기의 캐시**로 했다. 두 가지가 미해결이다.

1. **`margin` 을 val 에서 골라야 한다.** 지금 값은 test 에서 훑은 것이라
   65.9% 를 test 점수로 주장할 수 없다. 무조정 64.2% 만이 정직한 수치다.
2. **fine-tuned 검출기로 다시 재야 한다.** 새 검출기는 조각을 덜 낸다
   (예측 875 → 682, precision 59.3% → 82.3%). 병합할 조각 자체가 줄었으므로
   DB 유도 병합의 이득도 달라진다 — 커질 수도, 작아질 수도 있다.

둘 다 **val + test 캐시를 fine-tuned 검출기로 새로 만들면** 한 번에 해결된다.
그 캐시는 조건부 인식률 재측정(`m3_det_finetune.md` §4)에도 그대로 쓰인다.
