## 0. 프로젝트 컨텍스트

- **목표**: 산업용 자재/부품 마킹 코드(영숫자) OCR을 fine-tuning. 추론 결과를 후단 **시리얼 DB와 매칭**해 상위 후보를 사용자에게 제시·선택하게 한다.
- **프레임워크**: **PaddleOCR** (검출 + 인식 2단계). 라벨이 이미 PPOCR 포맷이라 전환 비용 최소.
- **실행 환경**: **Google Colab (GPU)**. 세션 휘발성·런타임 제한·VRAM 제약을 전제로 설계.
- **데이터**: **① 라벨 파일 `Label.txt` + ② 실제 이미지 파일 2,340장** (둘 다 필수).
  - `Label.txt`는 PPOCR det 포맷(`이미지경로\t[{"transcription":..., "points":[[x,y],...]}]`)으로 **경로만 담고 있으며, 실제 이미지 파일은 별도로 존재해야 한다.** 이미지 없이는 인식용 크롭 생성·곡면 폴리곤 크롭·학습 자체가 불가능하다.
  - 이미지 2,340 / 박스 8,103 / 고유 시리얼 약 4,281개(약 53% 유일값). 숫자 비중 약 60.6%.
  - 문자셋: 0-9 + A-Z + 기호(`- / . · ( ) : =` 공백). 소문자 잔여 3건은 대문자 정규화.
  - **곡면 텍스트**: 5점 이상 다각형 박스 99개(93 이미지). 실사용 대상. 평균 13.9자, 절반 이상 20자+, 69% 다중 토큰.
  - 다중 토큰(공백 포함) 박스 21.6%.

### 반드시 지켜야 할 확정 규칙 (위반 금지)
1. **문자 골격 정규화 금지**: `8↔B, 5↔S, 0↔O, 1↔I, 2↔Z`를 병합하지 말 것. `8135`/`B13S`, `83`/`B3` 등이 **둘 다 실존 코드**. 문자 사전(`dict.txt`)·평가·DB 매칭 어디서도 병합 금지. (혼동 문자 자동 탐지 정규화는 "오기 후보 탐지용" 국소 사용만.)
2. **대문자 정규화**: 문자 사전은 `0-9 + A-Z + 기호`. 소문자 a-z 미포함. 실사 소문자 3건(`166m84`,`Nav-D`,`E27C. 50X50X6t`)은 학습·평가에서 대문자로 정규화, 원값은 이력 보존.
3. **누수 방지 분할**: 동일 시리얼 값이 train/test에 동시 등장 금지(시리얼 값 단위 그룹 분할). 단, 학습 제외 시리얼도 **DB 프록시에는 포함**.
4. **곡면 분리 평가**: 곡면 서브셋 성능을 통합 지표에 합산하지 말 것.
5. **재현성**: 데이터 스냅샷·분할 시드·config·가중치·매칭함수 버전·|DB| 기록.

## TASK 1 — 라벨 전처리 (정제 완료 재현 + 박스 분할 게이트)

> 혼동 문자 정제·소문자 판정은 **이미 완료**(원본 대조). 이 TASK는 정제를 코드로 고정하고 **박스 분할 표준화**를 처리.

1. **대문자 정규화** 함수 구현. 소문자 3건 → 대문자, 원값은 `label_original`로 보존.
2. **문자 사전 생성**: `configs/dict.txt`에 실제 등장 문자(0-9, A-Z, 기호)만 나열. **소문자·미등장 문자 제외**. 이 사전이 인식기 출력 클래스를 정의.
3. **[게이트] 박스 분할 표준 확정**:
   - 공백 다중 토큰을 (a) 한 박스 유지+후처리 분리 / (b) 개별 분리 중 택1(기획서 권장 a).
   - 선택 방식으로 전체 라벨 일괄 정규화 + 규칙 문서화.
   - (a) 채택 시 토큰 경계 메타데이터를 남겨 TASK 7 공백 오류율 추적 대비.
4. **PaddleOCR 이중 포맷 생성**:
   - **검출용**: 기존 `Label.txt` 형식 유지(polygon + transcription).
   - **인식용**: 각 박스를 **폴리곤 기준으로 크롭**해 개별 이미지로 저장 + `이미지경로\t대문자정답` 매핑 파일 생성.
   - **[게이트] 4점 초과 폴리곤 크롭 — PaddleOCR 내장 함수로 불가, 직접 구현 필수**: PaddleOCR의 표준 크롭 함수(`tools/infer/utility.py`의 `get_rotate_crop_image`)는 **4점 입력만 받고, 5점 이상 폴리곤을 넣으면 `assert len(points) == 4`로 예외가 발생**한다(실사례: PaddleOCR GitHub Issue #5300, SAST 곡면 검출 결과를 그대로 넣었다가 크래시). 따라서 곡면 99박스는 다음 중 하나로 **별도 구현**해야 한다:
     - **(권장) Segment-based unrolling**: 폴리곤을 상단선/하단선으로 분리 → 각 선을 일정 간격으로 리샘플링 → `cv2.remap` 기반 TPS 워핑으로 평면화. 구현 검증(육안 확인 포함)을 TASK 1 단계에서 마친다.
     - **(대안, 구현 부담 클 때) 최소외접사각형 폴백**: 곡면 박스만 여유 있게 `cv2.minAreaRect`로 감싸 크롭하고, 곡률 보정은 인식기의 TPS(6-B A안)에 맡긴다. 구현은 간단하지만 크롭에 배경·인접 문자가 더 포함될 수 있다.
   - 4점 박스(8,004개)는 기존 `get_rotate_crop_image`를 그대로 사용해 문제없다.

**산출물**: `label_snapshot_v2`(정규화·분할 적용), `dict.txt`, 검출/인식 라벨 파일, 변환 규칙 문서.

## TASK 2 — 데이터 분할 (누수 방지, Colab에서 사전 계산)

1. **시리얼 값 단위 그룹 분할** + 이미지 단위 분할 병행 → 80/10/10. 동일 시리얼이 train/test 동시 등장 금지.
2. **곡면 층화 분할**: 곡면 이미지 93개를 train/val/test 비례 배분(train 곡면 0 방지). **test 배분 곡면 서브셋을 고정**(= 곡면 고정 검증셋).
3. **[게이트] 곡면 test 표본 부족 — 8:1:1 분할만으로는 지표를 신뢰할 수 없음**: 곡면 99박스를 8:1:1로 나누면 test에 약 10개 내외만 남는다. 이 규모에서는 **예측 1건의 성패가 지표를 약 10%p 흔들어**, Exact-match 같은 point estimate를 Exit Criteria로 쓰기에 통계적으로 불안정하다. 다음 중 하나를 필수로 채택한다:
   - **(권장, 기본안) K-Fold 교차검증 필수화**: 곡면 서브셋에 한해 5-Fold 등으로 학습·평가를 반복해 평균±표준편차로 보고. 매 실험(합성 배합비 스윕 포함)마다 반복하면 비용이 크므로, 최종 후보 1~2개로 좁힌 뒤 K-Fold로 확정 검증.
   - **(대안) 실사 전량 Test-only Anchor**: 실사 곡면 99건 전부를 평가 전용으로 고정하고, 학습에는 합성 곡면만 투입. **트레이드오프**: 표본 수는 늘어 지표가 안정되지만, 모델이 실제 파이프 곡률을 한 번도 학습에서 보지 못해 합성 곡률이 실물과 어긋나면 오히려 일반화가 나빠질 수 있다. 채택 시 TASK 5 합성 곡률 파라미터를 실사 곡면 이미지에서 직접 역산해 범위를 맞춰야 한다.
   - 두 방식 모두 사용 가능하면 K-Fold를 기본, Anchor 방식을 별도 안전판으로 병행 보고.
4. 분할 시드 고정·기록. 세트별 통계(박스 수, 곡면 비율, 고유값 수) 리포트.
5. 분할 결과를 검출·인식 각각의 train/val/test 라벨 파일로 출력.

**산출물**: `splits/split_seedXX.json`, 검출/인식용 분할 라벨 파일, 분할 통계 리포트, **곡면 K-Fold 폴드 목록(또는 Anchor 방식 채택 시 그 근거 문서)**.

## TASK 3 — 평가용 DB 프록시 & 기본 매칭 [게이트, 경량]

> **여기서는 "정의"만 한다. "튜닝"은 TASK 6 뒤로 미룬다.** Top-K가 주 KPI라 매칭 없이는 baseline(TASK 4)조차 주 KPI를 못 재므로 이 골격은 지금 필요하다. 단, 신뢰도 기반 튜닝은 실제 모델 출력 분포가 있어야 의미가 있으므로 아래 3-B로 분리했다(→ TASK 6-E).

1. **DB 프록시**: 정제 후 고유 시리얼(약 4,281) + (확보 시) 부품 마스터 합집합 → `serial_db_proxy_v1` 스냅샷. **그룹 분할로 학습에서 뺀 시리얼도 포함**.
2. **기본 매칭 함수**(`src/matching/match.py`): 정규화 편집거리(Levenshtein) 기반 Top-K 랭킹. 예측 → DB 조회 → 후보 K개.
   - **문자 골격 정규화 금지**(규칙 1). 대소문자 무시 비교만 허용.
   - **공백 처리 옵션**: 다중 토큰 통째 인식(TASK 1 (a)안) 시 CTC/attention 모두 공백 경계를 놓치기 쉽다(`ABC 123`→`ABC123` 등). 매칭 함수에 **원문 비교 + 공백 제거 비교를 모두 계산해 더 짧은 편집거리를 채택하는 옵션을 기본 탑재**한다. TASK 7-4의 공백 경계 오류율이 임계치를 넘으면 TASK 1의 (b)안(개별 박스 분할)으로 전환.
3. **|DB| 기록** 항상 포함.
4. **[중요] 예측 원본 아카이빙 규칙 수립**: TASK 4(baseline)·TASK 6(fine-tuned) 추론 시 **텍스트 예측값 + 문자별 확신도(logit/softmax)를 원본 그대로 저장**하도록 규약을 정한다(포맷만 여기서 정의). 이렇게 하면 TASK 6-E에서 매칭 튜닝이 완성된 뒤에도 baseline·fine-tuned 양쪽에 **소급 적용**해 Top-K를 재계산할 수 있다 — "매칭을 나중에 만든다"와 "baseline부터 Top-K를 잰다"가 충돌하지 않는 이유.

**산출물**: `matching/` 모듈(기본 버전), `serial_db_proxy_v1`, 매칭 테스트(`8135↔B13S`가 서로 매칭 안 되는지 검증), 예측 아카이빙 포맷 규약.

> **미룬 항목 → TASK 6-E로 이동**: 신뢰도 가중 동점 처리, 미등록 판정 임계값 튜닝. 실제 모델 출력이 없는 상태에서 정하면 추측에 불과하므로 인식 학습 이후로 미룬다.

## TASK 4 — Baseline 실측 [게이트: 목표선 확정]

1. PP-OCRv5 사전학습 모델(server det + rec)로 test셋 추론(fine-tuning 전). **TASK 3-4 규약대로 원본 예측(텍스트+문자별 확신도)을 아카이빙**(추후 TASK 6-E 매칭 튜닝 완성 후 Top-K 소급 재계산에 사용).
2. TASK 3 프록시 기준 지표 측정: CAR(정규화 편집거리 기반), Exact-match, Top-K@5 / Top-1(폐집합), **곡면 서브셋 분리**, 혼동 문자 오인식률(0/O,1/I,5/S,8/B,2/Z 혼동행렬).
3. **[게이트] 검출 fine-tuning 필요성 판단 — 검출 전용 지표를 반드시 분리 측정**:
   - **검출 recall/precision/Hmean**을 (a) 4점 평면 박스 서브셋(8,004개, 98.8%), (b) 곡면 서브셋(99개, 1.2%)으로 **나눠서** 측정. 통합 수치만 보면 곡면 실패가 평면 다수에 묻힌다.
   - **판단 기준**:
     - 평면 서브셋 Hmean ≥ 임계값(예: 95%) → **평면 검출은 fine-tuning 생략**하고 사전학습 검출기를 그대로 사용. 리소스를 인식 fine-tuning(TASK 6-B, 혼동 문자·긴 코드 대응이 이 프로젝트의 핵심 병목)에 우선 배분.
     - 평면 서브셋이 임계값 미달 → 검출 fine-tuning 필요(조밀한 다중 박스 레이아웃·박스 간 근접에서 recall 저하 가능성이 실제 있음, 상단 참조).
     - **곡면 서브셋은 별도 판단**: 사전학습 검출기가 곡면에서 유독 낮으면(도메인 시프트 가능성 높음), 전체 재학습이 아니라 **곡면 증강 데이터(TASK 5)만으로 짧게 이어서 학습(continued training)**하는 저비용 경로를 우선 검토 — 평면 검출 성능을 건드리지 않으면서 곡면만 보강.
   - 이 판단 결과를 `reports/det_finetune_decision.md`로 남기고, TASK 6-A는 이 결정에 따라 **조건부**로 진행(무조건 fine-tuning 아님).
4. `plan.md` 3.3 목표선 표를 실측값으로 채우고 **|DB| 확정 후 Top-K 목표선 재보정**.

**산출물**: `reports/baseline_v1.md`, `reports/det_finetune_decision.md`(검출 fine-tuning 필요 여부 및 근거).

## TASK 5 — 합성 데이터 생성 (실사 부족분 보완) [학습 데이터로 투입]

> **목적을 오해하지 말 것**: 합성 데이터는 검증용 비교군이 아니라 **실사 데이터의 부족분을 메워 학습에 실제 투입되는 학습 데이터**다. 특히 **곡면은 실사 99박스뿐이라 합성 보강 없이는 rectification 학습이 사실상 불가능**하다. 따라서 학습(TASK 6)보다 먼저 생성한다.

### 보완해야 할 부족분 (생성 우선순위)
| 부족분 | 실사 현황 | 합성으로 보완할 것 |
|---|---|---|
| **곡면 샘플** | 99박스(1.2%)뿐 | 평면 라벨 8,004건에 원통/아치 warping 적용해 인공 곡면 대량 생성 → TPS/rectification 학습 신호 확보 |
| **희소 혼동 문자** | `B16S` 1건 등 | `8/B, 5/S, 0/O, 1/I, 2/Z`가 충분히 등장하도록 균형 생성(실존 코드 구별축이므로 학습 신호 필수) |
| **긴 복합 코드** | 20자+ 코드 대부분 유일값 | 코드 문법으로 긴 조합 대량 생성 |
| **미등장 코드 조합** | 고유값 53%, 도메인 좁음 | 문법상 유효하나 실사에 없는 조합까지 커버 → 과적합 완화 |

### 생성 절차
1. **코드 문법 파라미터화**: `숫자4자리 + 문자코드 + 구분자(- /) + 접미(H1B 등)` 문법을 파라미터로 정의해 유효 조합을 생성. 문법은 **TASK 1의 정제된 라벨**에서 도출(정제 완료가 선행 조건 — 오염된 문법으로 생성하면 오류가 증폭됨).
2. **분포 균형화**: 위 표의 부족분이 충분히 등장하도록 문자·길이 분포를 의도적으로 조정.
3. **렌더링**: 도메인 폰트 + 실제 배경 텍스처 + **곡면 왜곡(원통/아치 warping)**. 인식용 크롭 이미지 형태로 생성(TASK 1의 크롭 규격과 동일하게 맞출 것). `text_renderer` 류 도구 활용 가능.
   - **[게이트] Colab I/O 병목 방지 — 개별 파일 저장 금지**: 합성 이미지를 수만 장 단위의 개별 PNG/JPG로 쓰면 Colab 로컬 디스크 I/O가 DataLoader 속도를 심하게 저하시킨다. 다음 중 하나로 패킹한다:
     - **(권장) LMDB 패킹**: PaddleOCR는 `Train/Eval.dataset.name: LMDBDataSet`을 config에서 그대로 지원한다(TASK 6 config와 자연스럽게 통합). 합성 이미지+라벨을 LMDB 1개로 묶어 저장.
     - **(대안) On-the-fly 생성**: `Dataset.__getitem__` 내부에서 실시간 렌더링/증강해 디스크에 아예 쓰지 않는 방식. 저장 공간 절약에는 유리하나 매 epoch 재생성 비용 발생 — 배합비 스윕(6-D)처럼 반복 실험이 많은 단계에서는 LMDB 사전 패킹이 더 유리.
   - 실사 인식용 크롭(TASK 1)도 동일하게 LMDB로 통합 패킹하면 실사+합성 혼합 로딩이 단순해진다.
4. **문자 사전 준수**: 생성 문자는 `dict.txt` 범위(0-9, A-Z, 기호) 내로 제한. 소문자 생성 금지. 골격 정규화 금지 규칙도 동일 적용(`8`과 `B`를 같은 것으로 취급해 생성하지 말 것).
5. **합성 데이터 태깅**: 각 샘플에 `source=synth` 메타를 붙여 실사와 구분(TASK 6 배합비 실험·평가 분리에 필요).

**산출물**: 합성 데이터셋(**LMDB 패킹**, Drive 압축 보관), 생성 문법·파라미터 문서, 실사/합성 분포 비교 리포트.

### 5-B. 실사 이미지 강건성 증강 (일반 Augmentation) — [기존 문서의 공백]
> **TASK 5(위)와 목적이 다르다.** 위 절차는 "코드 어휘·곡면 다양성"을 늘리는 것이고, 여기는 **실제 카메라 촬영 조건의 다양성**을 늘리는 것이다. 합성 텍스트만으로는 깨끗한 크롭에서만 강해지고, 실제 현장(손떨림·반사·오염·조명 변화)에서 정확도가 급락하는 전형적 실패를 막지 못한다. 산업 현장 배포를 전제로 한 이 프로젝트에서는 이 증강이 문자 인식 자체만큼 중요하다.

**① PaddleOCR 내장 증강 — config만 켜면 됨(구현 불필요)**
- PaddleOCR 인식 학습은 `RecAug` 연산자를 기본 제공한다: **블러, 가우시안 노이즈, 색상 지터(명도/채도, contrast·gamma 계열 포함), 원근왜곡(TIA distort/stretch/perspective), 랜덤 크롭, 색 반전**을 학습 중 실시간 적용(각 40~50% 확률).
- `configs/rec/<our_rec>.yml`의 `Train.dataset.transforms`에서 `RecAug`(+ 필요 시 `RandAugment`) 항목의 주석을 해제하고 확률 파라미터(`blur_prob`, `noise_prob`, `jitter_prob`, `hsv_aug_prob` 등)를 조정해 활성화.
- 검출 쪽은 `IaaAugment`(imgaug 래퍼)로 회전·리사이즈 등 지원. `configs/det/<our_det>.yml`에서 동일하게 확인·활성화.
- **이 항목은 목록의 Blur/Noise/Perspective/Contrast·Gamma를 커버한다.**

**② 도메인 특화 증강 — PaddleOCR 미지원, 직접 구현 필요**
다음은 표준 라이브러리에 없어 별도 구현이 필요하다: **Specular/Metal Reflection, Rust, Scratch, Oil, Dust, Motion Blur, Compression 아티팩트**.
- **구현 방식**: 실사 크롭(및 TASK 5 합성 크롭)에 대해 `Dataset.__getitem__` 내부 on-the-fly 변환으로 적용(LMDB 원본은 깨끗하게 유지하고, 로딩 시점에 랜덤 적용 — 매 epoch 다른 조합 노출).
  - Reflection/Metal Reflection: 랜덤 위치·강도의 하이라이트 마스크 합성(가우시안 블롭 + 스크린 블렌딩).
  - Rust/Oil/Dust: 텍스처 오버레이(반투명 알파 블렌딩) — 실제 마모된 부품 사진에서 텍스처 패치를 추출해 사용하면 더 사실적.
  - Scratch: 랜덤 방향의 얇은 선(밝기 대비) 합성.
  - Motion Blur: 방향성 커널 컨볼루션(`cv2.filter2D`, 랜덤 각도·길이).
  - Compression: JPEG 재인코딩(랜덤 품질 20~70)으로 아티팩트 재현.
- **[게이트] 배포 맥락에 맞는 것만 채택**: 이 증강들을 전부 무분별하게 넣지 않는다. 신품 부품(공장 출고 직후)인지 사용 중/야외 보관 부품(마모·오염 노출)인지에 따라 관련 항목이 달라진다. TASK 5의 합성 검증 게이트와 동일한 원칙 적용 — **증강 유무·강도별로 실사 검증셋에서 비교**해, 실제 개선을 주는 항목만 채택하고 무관한 항목은 제외(불필요한 증강은 학습 신호를 흐릴 뿐 효과가 없다).
- **실제 마모 샘플 확보 시도**: 가능하면 실사 이미지 중 마모·오염이 있는 샘플을 별도 태깅해, 합성 열화 파라미터(스크래치 굵기·녹 색상 등)를 실측에 맞춰 보정.

**산출물**: `src/preprocess/augment.py`(내장+커스텀 증강 모듈), 활성화된 `RecAug`/`IaaAugment` config, 커스텀 열화 연산자 코드, **증강 항목별 채택/제외 근거 리포트**(TASK 6-D 배합비 스윕과 동일한 형식으로 실사 검증셋 비교).

## TASK 6 — PaddleOCR 학습 (검출 + 인식) [단계화 실행 — 한 번에 한 변수만]

> **실험 격리 원칙(Staging Discipline)**: 아래 5개 요소(인식 기본기, 검출, 합성, TPS/곡면, 매칭 튜닝)를 한 실험에 몰아넣지 않는다. **매 단계는 이전 단계에서 확정된 체크포인트 위에 변수 하나만 추가**하고, 추가 전/후를 실사 검증셋에서 비교해 그 변수의 순효과를 분리 측정한다. 이렇게 해야 최종 결과가 기대에 못 미칠 때 어느 단계가 원인인지 즉시 특정할 수 있다. 아래 5단계는 순서대로 진행하며(Colab 세션이 허용하는 한 각 단계를 별도 세션으로 분리 권장), 각 단계 종료 시 체크포인트를 Drive에 태깅해 보존한다.

| 단계 | 무엇을 추가하는가 | 비교 기준 |
|---|---|---|
| **1. 인식 기본기** | SVTR/PP-OCRv5 rec(B안, TPS 없음) fine-tuning. 곡면은 TASK 1 크롭 보정에만 의존 | TASK 4 baseline 대비 |
| **2. 검출** | *(조건부, TASK 4 판단 시에만)* DBNet fine-tuning | 1단계 체크포인트(검출은 사전학습 유지) 대비 |
| **3. 합성** | TASK 5 합성 데이터를 학습에 추가(배합비 스윕) | 직전 체크포인트(실사만) 대비 — 6-D |
| **4. TPS/곡면 업그레이드** | RARE(TPS 내장)로 교체 실험. **3단계까지의 SVTR 체크포인트가 이미 존재하므로, "TPS가 실제로 이득인가"를 깨끗하게 비교 가능** | 3단계 체크포인트(SVTR+합성) 대비, 곡면 고정 검증셋 기준 |
| **5. 매칭 튜닝** | 신뢰도 가중·임계값(6-E) | 4단계까지 확정된 최종 인식 모델의 실제 출력 분포 기준 |

각 단계는 아래 6-A~6-E의 세부 내용을 그대로 따르되, **순서와 격리 원칙만 이렇게 강제**한다. (검출을 2단계에 배치한 건 무조건 학습이 아니라 "필요하면 이 시점에" — TASK 4 조건부 판단은 유지.)

### 6-A. 검출 (Detection) — [조건부, 2단계] TASK 4 판단 결과에 따라 진행 여부 결정
> **무조건 fine-tuning하지 않는다.** TASK 4-3의 `det_finetune_decision.md`에서 평면 검출이 이미 임계값을 충족했다면 이 단계는 생략하고 사전학습 검출기를 그대로 파이프라인에 연결한다. **1단계(인식 기본기)를 먼저 완주**한 뒤, 검출은 TASK 4 판단에 따라 필요한 경우에만 이어서 진행한다 — 검출을 건너뛰면 원인 규명 대상에서 아예 제외되므로 오히려 유리하다.
- **모델**: **PP-OCRv5 server det (DBNet 계열)** fine-tuning. DBNet은 곡면·회전 텍스트를 **폴리곤**으로 검출하므로 이 데이터에 적합(사각형 전용 검출기 금지).
- **사전학습 가중치**: PP-OCRv5 server det는 공식 model zoo에 배포되어 있어 가용성 확인 없이 바로 사용 가능(인식과 달리 별도 확인 불필요).
- **config**: `configs/det/`의 DB 계열 yml 복제 → 다음 수정:
  - `Global.pretrained_model` = PP-OCRv5 server det 가중치 경로.
  - `Train/Eval.dataset.data_dir`, `label_file_list` = TASK 2 검출 라벨.
  - `Global.save_epoch_step` 짧게(Colab 세션 대비), `Global.checkpoints`로 resume 설정.
  - `Global.use_gpu=True`, `Optimizer`·`batch_size_per_card`를 GPU VRAM에 맞춰 조정.
- 학습: `python tools/train.py -c configs/det/<our_det>.yml`.

### 6-B. 인식 (Recognition) — [1단계: SVTR/B안 우선, 4단계: RARE/TPS 업그레이드]

#### 사전학습 가중치 — 확인 완료 (둘 다 실존, 단 세대·품질 차이가 진짜 결정 축)
- **(A) PP-OCRv5 rec (SVTR_LCNet 계열)**: 공식 배포 확인됨(server/mobile, `PP-OCRv5_server_rec_pretrained.pdparams`). 최신 세대·고정확 backbone.
- **(B) RARE / StarNet (TPS 내장)**: **사전학습 가중치 확인 완료** — PaddleOCR 공식 저장소(`docs/version2.x/algorithm/overview.en.md`)에 실제 다운로드 URL이 명시돼 있다(MJSynth+SynthText로 학습, DTRB 벤치마크):
  - StarNet ResNet34_vd (82.85%): `https://paddleocr.bj.bcebos.com/dygraph_v2.0/en/rec_r34_vd_tps_bilstm_ctc_v2.0_train.tar`
  - RARE ResNet34_vd (83.98%): `https://paddleocr.bj.bcebos.com/dygraph_v2.0/en/rec_r34_vd_tps_bilstm_att_v2.0_train.tar`
  - RARE MobileNetV3 (81.76%): `https://paddleocr.bj.bcebos.com/dygraph_v2.0/en/rec_mv3_tps_bilstm_att_v2.0_train.tar`
  - **주의**: 이건 2020~2021년 v2.0 dygraph 세대의 **구형·경량 백본**(ResNet34_vd/MobileNetV3)이다. PP-OCRv5 rec(SVTR 기반)보다 세대가 뒤처지고 벤치마크 평균 정확도도 낮다(82~84% vs PP-OCRv5의 더 높은 최신 수치). **가용성은 더 이상 쟁점이 아니며, 진짜 결정 축은 "곡면 대응(TPS 내장)을 위해 구형·저정확 백본을 감수할 가치가 있는가"이다.**
- **[게이트] 링크 생존 확인만 남음**: 위 URL은 2020~2021년 게시물이라 bcebos 링크가 간헐적으로 만료될 수 있다. 학습 착수 시 `wget`으로 실제 다운로드가 되는지만 빠르게 확인(가용성 자체는 재조사할 필요 없음). 실패 시 PaddleOCR GitHub Discussions에서 최신 미러 링크 확인.

#### 모델 후보 2안 — 곡면 처리 방식이 핵심 (순차 진행, 동시 비교 아님)
- **(1단계, 먼저) B안 — SVTR / PP-OCRv5 rec**: 최신·고정확 backbone이나 rectification 미내장. **TASK 1의 폴리곤 크롭 정규화(휜 영역을 미리 편 크롭)**로 곡면을 보정해 입력. 이걸로 먼저 end-to-end 파이프라인을 완주해 안정적 체크포인트를 확보한다.
- **(4단계, 나중) A안 — RARE(TPS 내장)**: RARE(ResNet34_vd, 83.98%)로 교체 실험. 곡면 크롭을 평면으로 편 뒤 인식하므로 구조적으로 곡면에 부합하나, **1단계 체크포인트가 이미 있어야 "TPS 교체가 실제로 이득인가"를 깨끗하게 비교**할 수 있다.
- **결정 규칙**: 4단계에서 A안 도입 후 **곡면 고정 검증셋(TASK 2-2)**에서 1단계(B안) 대비 성능을 비교. 개선되면 A안 채택, 아니면 B안 유지(F1/F2 폴백 매트릭스와 연결).
- **config**: `configs/rec/`의 해당 yml 복제 →
  - `Global.pretrained_model` = 해당 단계에서 확인된 가중치 경로(필수 — 빈 값으로 처음부터 학습 시작하지 말 것).
  - `Global.character_dict_path` = TASK 1 `dict.txt`로 교체. **주의**: 원본 사전학습 가중치는 `en_dict.txt`(자체 문자 클래스) 기준으로 학습됐으므로, 최종 분류 헤드(FC/Head)는 클래스 수 불일치로 자동 재초기화된다(백본·인코더는 그대로 전이). 이는 정상 동작이며 별도 조치 불필요.
  - `Global.use_space_char`는 다중 토큰 정책에 맞게 설정.
  - `Global.max_text_length` = 실측 최댓값(24자+ 여유) 이상.
  - `Train/Eval.dataset` = TASK 2 인식 라벨(크롭 이미지).
  - 체크포인트 자주 저장 + resume.
- 학습: `python tools/train.py -c configs/rec/<our_rec>.yml`.

### 6-C. 학습 전략 (단계별 적용 범위)
- **[전 단계 공통]** 인식은 항상, 검출(2단계)은 TASK 4 판단에 따라 조건부로 사전학습 가중치에서 fine-tuning(좁은 도메인이므로 처음부터 학습보다 우선). **AMP(혼합정밀)** 활성화로 Colab VRAM 여유 확보.
- **[1단계부터 적용]** **혼동 문자 집중**: `8/B,5/S,0/O,1/I,2/Z` 오분류에 가중(loss 가중 또는 해당 문자 포함 샘플 오버샘플링/hard example mining). 이 문자들은 실존 코드 구별축이며 곡면·합성과 무관하게 항상 유효하므로 1단계부터 켠다.
- **[3단계에서 추가]** **학습 데이터 = 실사 + 합성(TASK 5) + 강건성 증강(TASK 5-B)**. 1~2단계는 실사(+증강)만으로 진행하고, 합성은 3단계에서 독립 변수로 추가해 순효과를 분리 측정한다(아래 6-D).
- **[4단계에서 적용]** **TPS 학습**(RARE 채택 시): 곡면은 합성 보강분이 학습 신호의 대부분을 차지하므로, **실사 곡면 서브셋 성능을 게이트로 점진 조정**(합성 곡률 과적합 방지).

### 6-D. [3단계, 게이트] 합성 배합비 결정 및 역효과 감시
> 합성을 **쓸지 말지**가 아니라 **얼마나 섞을지**를 정하고, 합성 특유 패턴 과적합을 감시하는 단계다. **1단계(실사+증강만) 체크포인트가 기준선이므로, 이 시점부터는 합성 추가의 순효과만 깨끗하게 측정된다.**

- **배합비 스윕**: 합성:실사 = 1:1 / 3:1 / 5:1로 각각 학습해 **실사 검증셋(합성 미포함)**에서 성능 비교.
- **기준선 확보**: 1단계 체크포인트(`실사만`)를 기준선으로 함께 측정해 합성의 순효과를 정량화.
- **꺾이는 지점 탐지**: 합성 비율을 올릴수록 실사 성능이 개선되다 하락 전환하는 지점을 찾아 **최적 배합비 확정**.
- **곡면 과적합 회귀 감시**: 합성 곡면으로 rectification을 학습했으므로, **실사 곡면 고정 서브셋(TASK 2-2)** 성능이 하락하지 않는지 매 실험 확인. 하락 시 곡률 파라미터 범위 재조정 또는 합성 곡면 비율 축소.
- 결과를 배합비 결정 리포트로 남기고, 확정된 비율로 3단계 최종 체크포인트를 확정(4단계 TPS 실험의 기준선이 됨).

**산출물(1~4단계 공통)**: 단계별 체크포인트(Drive, 각 단계 종료 시 태깅 보존 — 롤백 가능해야 함), `reports/rec_backbone_comparison.md`(4단계: TPS 내장 vs 1단계 SVTR, 곡면 검증셋 실측 비교), 사용 config, 가중치 해시, 학습 로그(VisualDL), 배합비 스윕 결과 및 최적 비율 확정 리포트(3단계).

### 6-E. [5단계, TASK 3에서 이동] 매칭 튜닝 — 신뢰도 가중·미등록 판정 임계값
> 이제 실제 인식 모델의 예측 분포·확신도 분포가 존재하므로, TASK 3에서 정의만 해두고 미뤘던 튜닝을 여기서 완성한다.

- **동점 처리(신뢰도 가중)**: 편집거리가 동일한 후보가 여럿이면(`A123B` vs DB의 `A123C`/`A123D` 등) 확정된 인식 모델의 문자별 확신도(logit/softmax confidence)로 가중해 순위를 정한다. **주의(규칙 1과의 경계)**: 이 가중은 편집거리가 같은 후보들 사이의 순위만 조정하는 것이며, `8`과 `B`처럼 서로 다른 실존 문자를 같은 것으로 접어서 거리를 0으로 만드는 것이 아니다. 골격 정규화(문자 병합)와 신뢰도 가중(순위 조정)은 별개이며 후자만 허용한다.
- **미등록 판정 임계값 튜닝**: TASK 6-B/D로 확정된 모델의 실제 확신도 분포를 보고 "후보 없음/신뢰도 낮음" 임계값을 실측 기반으로 설정(폐집합 이탈 시 오검출·미검출 트레이드오프를 실제 분포로 조정).
- **소급 적용**: TASK 4에서 아카이빙해둔 baseline 원본 예측(TASK 3-4)에도 동일 매칭 함수를 적용해 baseline Top-K를 재계산 — 학습 전후 주 KPI를 공정하게 비교.

**산출물**: `matching/` 모듈(튜닝 완료 버전), `reports/matching_tuning_v1.md`(임계값·가중치 근거), baseline·fine-tuned 양쪽 Top-K 재계산 리포트.

## Fallback 전략 매트릭스 (실패 시 대응) — [기존 문서의 공백]

> 지금까지 문서 곳곳의 게이트는 "실측해서 비교 후 채택"까지만 정의돼 있고, **측정 결과가 나쁠 때 무엇을 할지**는 빠져 있었다. 게이트마다 트리거 조건과 구체적 대응 행동을 짝지어 둔다. "그때 다시 생각한다"를 프로젝트 전략으로 쓰지 않는다.

| # | 리스크 | 트리거 조건 | Fallback 행동 |
|---|---|---|---|
| F1 | **RARE(TPS 내장) 실패** (4단계 실험) | 곡면 검증셋에서 RARE가 수렴 안 되거나 1단계 SVTR 체크포인트보다 낮음 | **즉시 1단계 체크포인트(SVTR/PP-OCRv5 rec)로 롤백**. 곡면 대응은 TASK 1의 폴리곤 크롭 정규화(segment unrolling)에 전적으로 의존. TPS 관련 학습 전략(6-C)은 폐기. 4단계를 건너뛴 것으로 기록하고 5단계(매칭 튜닝)로 진행. |
| F2 | **1단계(SVTR) 자체가 부진** | 1단계 완료 시점에 baseline 대비 유의미한 개선 없음 — **가장 이른 단계에서 조기 발견되므로 이후 단계(검출·합성·TPS) 착수 전에 원인부터 해결** | (a) mobile/경량 backbone으로 교체 실험, (b) **곡면 전용 별도 모델**을 운영해 2-모델 앙상블(평면은 SVTR, 곡면은 별도 특화 모델), (c) 크롭 품질이 원인이면 TASK 1 크롭 알고리즘 재검증이 선행 원인일 수 있음 — 인식기 교체 전에 크롭 품질부터 육안 샘플링 점검. 1단계가 해결되기 전에는 2~5단계로 진행하지 않는다. |
| F3 | **합성 데이터 전면 실패** (3단계, 모든 배합비에서 실사 대비 악화) | 6-D 배합비 스윕(1:1/3:1/5:1) 전부가 1단계 체크포인트(`실사만`)보다 낮음 | 합성 **전면 폐기**하고 1단계 체크포인트로 롤백, 실사 전용으로 4단계(TPS)로 직행. 부족분 보완은 (a) **실사 데이터 추가 수집**으로 전환(우선순위: 곡면·희소 혼동 문자), (b) 곡면은 TASK 2-3의 Anchor 방식(실사 전량 평가 전용)으로 좁혀 기대치를 낮춤. 단순 폐기가 아니라 왜 실패했는지(폰트·질감 불일치, 곡률 파라미터 오차 등) 원인 진단 리포트를 남겨 향후 재시도 근거로 보존. |
| F4 | **곡면 성능이 끝까지 목표 미달** (F1~F3 대응 후에도 곡면 지표가 임계 이하) | TASK 7 반복 3회 후에도 곡면 서브셋 지표가 목표선 미도달 | **비즈니스 레벨 폴백으로 전환**: 곡면 예측을 자동 매칭에 바로 태우지 않고, 신뢰도 낮은 곡면 예측은 현장 UI에서 **"수동 확인 필요"로 별도 플래그**(Human-in-the-loop). 자동화 스코프를 평면 텍스트로 한정하고, 곡면은 별도 로드맵(예: 촬영 가이드 개선, 데이터 추가 수집)으로 분리해 이번 릴리스 밖으로 이연. |
| F5 | **Detection fine-tuning을 했는데도 목표 미달** (TASK 4에서 fine-tuning 필요 판정 후, 실제 학습해도 개선 없음) | fine-tuning 후 recall/precision이 여전히 임계 미달 | (a) DB 후처리 파라미터(`unclip_ratio`, `thresh`, `box_thresh`) 튜닝 우선 시도(재학습보다 저비용), (b) 다른 검출 아키텍처(PSENet/FCENet) 비교, (c) 최종 폴백으로 **현장 앱에서 사용자가 관심영역(ROI)을 수동 지정**하는 반자동 모드 제공 — 검출을 아예 우회. |
| F6 | **Top-K 매칭 목표 미달** (TASK 7 최종 평가에서 시스템 KPI 미도달) | Top-K@5가 목표선(3.3, |DB| 재보정 후) 미도달 | (a) UI 후보 개수 K를 확대(예: 5→8)해 재현율 우선, (b) 매칭 UI에 **수동 검색 폴백** 추가(부분 문자열 검색), (c) 확신도 낮은 예측은 자동 매칭 생략하고 원문 그대로 표시해 사용자가 직접 판단하게 함. |
| F7 | **Colab 세션/리소스 한계로 학습 자체가 반복 실패** | 세션 만료·OOM이 반복돼 어느 실험도 완주 못 함 | 배치 크기·이미지 해상도 추가 하향, 실험을 더 작은 단위로 쪼개기(예: 배합비 스윕을 순차가 아닌 개별 세션으로), 필요 시 Colab Pro/Pro+ 또는 다른 GPU 환경으로 전환 검토. |

**운영 원칙**: 각 Fallback이 실제로 발동하면 `reports/fallback_log.md`에 트리거 조건·발동 시각·선택한 대응·근거를 기록한다(재현성 규칙과 동일 원칙 — 나중에 "왜 이 경로로 갔는지" 추적 가능해야 함).

## 진행 순서 요약

```
TASK 0 (Colab 스캐폴딩 + [게이트] 이미지 자산 정합성 검증)
  → TASK 1 (전처리·dict·박스분할 게이트 + [게이트] 4점 초과 폴리곤 크롭 직접 구현)
  → TASK 2 (누수방지 분할 + [게이트] 곡면 K-Fold/Anchor 필수화)
  → TASK 3 ([게이트, 경량] DB프록시·기본 매칭 정의 + 예측 아카이빙 규약 = 주 KPI 측정 가능화. 튜닝은 6-E로 이동)
  → TASK 4 ([게이트] PP-OCRv5 baseline 실측(원본 예측 아카이빙) + 검출 fine-tuning 필요성 판단(평면/곡면 분리) → 목표선 확정)
  → TASK 5 (합성 데이터 생성 = 실사 부족분 보완 + [게이트] LMDB 패킹/온더플라이 / **5-B 실사 강건성 증강**: 내장(Blur·Noise·Perspective) config 활성화 + 도메인 특화(반사·녹·스크래치·기름·먼지·압축) 직접 구현 [게이트: 배포 맥락 검증])
  → TASK 6 [단계화, 한 번에 한 변수만]
      1단계: 인식 기본기(SVTR, TPS 없음, 실사만) → baseline 대비 확인
      2단계: [조건부] 검출 fine-tuning(TASK 4 판단 시에만)
      3단계: [게이트] 합성 배합비 스윕 → 1단계 대비 순효과 확정
      4단계: TPS/RARE 업그레이드 실험 → 3단계 대비 곡면 개선 여부 확정(F1/F2 폴백)
      5단계: 매칭 튜닝(6-E, 신뢰도 가중·임계값) + baseline Top-K 소급 재계산
  → TASK 7 (export·평가·반복, Exit Criteria)
```

**데이터 흐름 요약**: 실사(이미지 2,340 + 라벨) → 정제·크롭 → 분할 → 1단계 인식 기본기(체크포인트 A) → (필요 시) 검출 → **3단계 합성 추가(체크포인트 B, A 대비 순효과 확정)** → **4단계 TPS 업그레이드(체크포인트 C, B 대비 곡면 개선 확정)** → 5단계 매칭 튜닝 → 평가. **각 화살표는 변수 하나만 추가한 비교이며, 문제 발생 시 마지막으로 추가한 변수부터 의심한다.**

**Colab 유의**: 매 학습은 체크포인트 저장+resume 필수. 세션 끊김·VRAM OOM은 정상 상황으로 간주하고 배치·해상도·AMP로 대응. 모든 산출물은 Drive에 저장.
